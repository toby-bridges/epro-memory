# ePro Memory — 让你的 AI 助手拥有长期记忆

> 想象一下：你有一个新同事，每天早上来上班都失忆了。你说过的偏好、做过的项目、踩过的坑——全部从零开始。
>
> ePro Memory 解决的就是这个问题。它让 AI 助手像一个真正的老同事一样，**越用越懂你**。

---

## 它解决了什么问题？

你可能遇到过这些场景：

| 没有记忆的 AI | 有 ePro Memory 的 AI |
|-------------|---------------------|
| "你喜欢什么风格的代码？" ——每次都要重新说 | 它已经知道你偏好简洁风格，直接按你的习惯来 |
| "这个项目的背景是什么？" ——每次都要从头解释 | 它记得这个项目是什么、你做了哪些决策 |
| 上次聊的解决方案，这次又要重新想一遍 | 它记得上次踩坑的经验，直接告诉你怎么绕开 |

一句话总结：**AI 不再是金鱼记忆，而是一个能积累经验的长期搭档。**

---

## 它是怎么工作的？

不需要你做任何事。整个过程是**全自动**的。

### 1. 自动记笔记（Memory Extraction）

每次你和 AI 聊完之后，ePro 会像一个勤快的助理一样，自动把这次对话里的重要信息整理成笔记存起来。

你不需要说"记住这个"——它自己会判断哪些值得记。

### 2. 自动翻笔记（Memory Recall）

下次你开始新对话时，ePro 会在后台快速翻阅之前的笔记，把跟你当前话题相关的内容悄悄递给 AI。

就像一个老同事在开会前，先帮你把相关的会议纪要翻出来放在桌上。

### 3. 自动去重（Deduplication）

如果你多次聊到同一件事，ePro 不会傻傻地存很多份重复笔记。它会自动识别：

- **这是新信息** → 新建一条记忆
- **这是已有信息的补充** → 合并到已有记忆里
- **这是重复的** → 跳过，不浪费空间

## 它能记住什么？

ePro 会把记忆分成 **6 个类别**，就像一份人事档案有不同的栏目：

### 关于你的（User Memory）

| 类别 | 档案类比 | 举例 |
|------|---------|------|
| **个人信息** (profile) | 身份证页 | "用户是一名前端工程师，在深圳工作" |
| **偏好习惯** (preferences) | 性格备注 | "喜欢用 TypeScript，不喜欢写注释" |
| **相关事物** (entities) | 项目经历页 | "正在做的项目叫 OpenClaw，是一个 AI 助手框架" |
| **发生过的事** (events) | 大事记 | "2月15日决定把数据库从 SQLite 换成 LanceDB" |

### 关于 AI 自身经验的（Agent Memory）

| 类别 | 档案类比 | 举例 |
|------|---------|------|
| **问题与解法** (cases) | 案例库 | "用户遇到内存泄漏，最后发现是事件监听器没清理" |
| **可复用的方法** (patterns) | 操作手册 | "部署这类项目时，先跑测试再推代码" |

## 记忆的三层结构

每条记忆不是一坨文字，而是像书一样有不同的"读法"：

| 层级 | 类比 | 用途 |
|------|------|------|
| **L0**（一句话摘要） | 书名 | AI 快速浏览时看这个，判断相不相关 |
| **L1**（结构化概要） | 目录 | 需要更多细节时看这个 |
| **L2**（完整记录） | 全文 | 需要深入了解时才翻开 |

为什么要分层？因为 AI 的注意力也是有限的。如果每次都把所有记忆的全文塞给它，反而会"信息过载"。分层让它**先看书名，觉得相关了再翻目录，必要时才读全文**。

## 一个完整的例子

假设你第一次告诉 AI：

> "我喜欢用 Tailwind CSS，不喜欢写内联样式。"

**ePro 在幕后做的事：**

1. 对话结束后，ePro 自动识别出这是一条「偏好习惯」
2. 创建一条记忆：
   - L0：用户偏好 Tailwind CSS，不喜欢内联样式
   - L1：CSS 偏好 — 使用 Tailwind 工具类，避免 inline style
   - L2：（完整的上下文细节）
3. 存储到本地数据库

**两周后，你开始一个新对话：**

> "帮我写一个登录页面的样式。"

**ePro 在幕后做的事：**

1. 看到"样式"这个关键词，自动在记忆中搜索相关内容
2. 找到之前存的 CSS 偏好记忆
3. 悄悄把这条信息递给 AI

**结果：** AI 直接用 Tailwind CSS 写样式，不会问你"要用什么 CSS 方案"，也不会写出你讨厌的内联样式。

## 关于"向量搜索"

你可能在 README 里看到过这个词。简单解释：

普通搜索是**精确匹配关键词**——你搜"苹果"，只能找到包含"苹果"两个字的内容。

向量搜索是**按意思找**——你搜"水果"，它也能找到关于"苹果""香蕉""橘子"的内容，因为它理解这些词在意思上是接近的。

ePro 用向量搜索来找记忆，所以即使你换了说法，它也能找到相关的旧记忆。就像一个聪明的图书馆管理员，你说"我想看关于做菜的书"，他不会只去找书名带"做菜"的，还会把"食谱""烹饪""厨艺"相关的书也帮你翻出来。

## 它在哪里存东西？

所有记忆都存在**你自己的电脑上**，默认路径是：

```
~/.clawdbot/memory/epro-lancedb
```

- 不上传到云端
- 不发送给第三方
- 你的数据只属于你

（技术说明：使用 LanceDB —— 一个嵌入式数据库，不需要你安装或运行任何额外的数据库软件。）

## 常见问题

**Q：我需要手动告诉它"记住这个"吗？**
不需要。ePro 会自动判断哪些对话内容值得记住。

**Q：它会把所有聊天内容都存下来吗？**
不会。它只提取有价值的信息，而不是逐字存储对话。就像你听完一场会议，只记重点，不会把每句话都写下来。

**Q：如果它记错了怎么办？**
记忆是可以管理的。后续版本会提供查看和删除记忆的工具。

**Q：它会让 AI 变慢吗？**
几乎感觉不到。记笔记在对话结束后进行，翻笔记在对话开始前完成，都不影响你和 AI 的实时交流。

**Q：需要联网吗？**
记忆存储在本地，不需要联网。但记忆的"整理"和"搜索匹配"需要调用 AI 模型的接口（Embedding API），这部分需要网络。

| **目的** | 让 AI 更懂你的工作上下文 | 让 AI 更懂你这个人 |

两个项目可以同时使用，互不冲突。一个让 AI 成为更好的工作搭档，一个让 AI 成为更懂你的朋友。
