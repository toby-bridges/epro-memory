# OpenClaw 记忆系统用户指南

> 你的 AI 助手每次对话都从零开始——不记得你的偏好，不记得做过的项目，不记得上次踩过的坑。
>
> OpenClaw 的记忆系统解决的就是这个问题。它由两个项目组成：**memX** 让 AI 记住关于**你**的事，**ePro** 让 AI 记住**它自己的工作经验**。

## 全景：OpenClaw 的记忆架构

OpenClaw 是核心——你的私人 AI 助手框架，运行在你自己的设备上，通过 WhatsApp、Telegram、Discord 等渠道和你对话。

但光有对话能力不够。想象你有一个非常聪明的新同事，但他每天早上来上班都**失忆**了。你昨天告诉他的偏好、一起做的项目、踩过的坑——全部归零。

为了解决这个问题，我们围绕 OpenClaw 开发了两个记忆项目：

```
                        ┌────────────────────┐
                        │     OpenClaw       │
                        │   (你的 AI 助手)    │
                        └────────┬───────────┘
                                 │
                    ┌────────────┼────────────┐
                    │            │            │
              ┌─────┴─────┐ ┌───┴───┐ ┌──────┴──────┐
              │   memX    │ │  ePro │ │    QMD      │
              │ 用户记忆   │ │ 工作经验│ │  项目文档    │
              │(MCP Server)│ │(Plugin)│ │(MCP Server) │
              └───────────┘ └───────┘ └─────────────┘
```

三个组件各管一件事：
- **memX** — 记住关于**你**的一切（偏好、背景、人际关系）
- **ePro** — 记住 AI 的**工作经验**（踩过的坑、有效的方案、项目背景）
- **QMD** — 索引你的**项目文档和代码**

它们同时运行、互不冲突，共同让你的 AI 助手变得越来越懂你、越来越能干。

### MCP Server 和 Plugin 是什么意思？

你可能注意到 memX 标注的是 "MCP Server"，ePro 标注的是 "Plugin"。这是两种不同的接入方式：

- **MCP Server**（memX 的方式）：像一个独立运行的服务，通过标准协议（Model Context Protocol）和 OpenClaw 通信。好处是**通用**——不只 OpenClaw 能用，Claude Desktop、Claude Code 等任何支持 MCP 的客户端都能用。
- **Plugin**（ePro 的方式）：直接嵌入 OpenClaw 内部，作为它的一个模块运行。好处是**轻量、响应快**，与 OpenClaw 紧密集成。

类比：MCP Server 像一家外部咨询公司（独立运营，很多公司都能请它）；Plugin 像公司内部的一个部门（只服务本公司，但效率更高）。

## 两种记忆：一个关于你，一个关于它

这是理解整个系统最关键的一个区分：

|  | memX（用户记忆） | ePro（智能体记忆） |
|--|-----------------|-------------------|
| **记的是谁** | 你——用户本人 | AI 助手自己 |
| **类比** | 你的私人日记本 | 员工的工作笔记 |
| **记什么** | 你的偏好、身份、人际关系、生活事件 | 工作中踩的坑、有效的解决方案、项目背景 |
| **谁在看** | 所有和你对话的 AI | 执行任务的那个特定 AI |
| **变化速度** | 慢——你的偏好不常变 | 快——每次工作都可能学到新东西 |

为什么要分开？因为这两种记忆的**性质完全不同**。

你的名字、你喜欢的编程语言、你的工作背景——这些是稳定的个人信息，应该被长期保存，衰减得很慢。

而"上次部署时遇到的 ffmpeg 编码问题"——这是工作经验，高频产生，可能很快过时，需要不同的管理策略。

把两种本质不同的信息塞进同一个系统，就像把日记和工作日志写在同一个笔记本里——找起来困难，管理起来混乱。

## memX — 用户记忆（MCP Server）

### 它做什么？

memX 记住**关于你这个人**的事情。当你告诉 AI "我喜欢用 TypeScript"，下周再开新对话时，AI 已经知道了——不用你再说一遍。

### 它有多"聪明"？

memX 不是简单地存一句话然后原样返回。它有几个独特能力：

**记忆会衰减** — 就像人的记忆。你经常提到的事情会被强化（"他真的很在意代码风格"），很久没提的事会慢慢变淡。这不是 bug，而是特性——让最相关的记忆浮上来，过时的自然沉下去。

**记忆有层级** — 分为核心层、工作层、边缘层。你的名字和身份在核心层，几乎不会忘；最近聊的项目细节在工作层，会缓慢衰减；一次性提到的琐碎信息在边缘层，衰减最快。

**去重不傻** — 你说过"我喜欢简洁的代码"，后来又说"我偏好精炼的代码风格"。系统知道这是同一件事的不同说法，会自动合并。你说"我不再用 Vue 了，改用 React"，系统知道要**更新**旧记忆，而不是同时保留两条矛盾的信息。

**有知识图谱** — 不只存孤立的事实，还能理解事物之间的关系。比如知道"你 → 正在做 → 项目 A"、"项目 A → 使用 → TypeScript"、"TypeScript → 是 → 编程语言"。这让搜索结果更有关联性。

### 技术选择

| 方面 | memX 的选择 | 为什么 |
|------|------------|--------|
| 运行在哪 | 你的 Mac 本地 | 个人记忆是隐私数据，不该上传云端 |
| AI 推理 | Ollama（本地模型） | 零云端调用，零额外费用 |
| 存储 | SQLite | 成熟、可靠、支持复杂查询 |
| 搜索 | 三通道融合（向量 + 关键词 + 图谱） | 单一搜索方式各有盲区，三路融合最稳健 |

## ePro — 智能体记忆（Plugin）

### 它做什么？

ePro 记住的是 **AI 助手自己的工作经验**。

一个例子：你的 AI 助手第一次帮你处理视频文件，用 ffmpeg 合并多个片段时踩了一个坑——输入文件的编码格式不统一，导致输出损坏。它花了一些功夫才解决。

**两周后**，同样的任务来了。
- 没有 ePro：AI 会重新踩同样的坑
- 有 ePro：AI 在开始工作前就收到提醒——"上次做这个任务的经验：先检查输入文件编码是否一致"

更进一步，如果 AI 处理了多个类似案例，ePro 会把它们**蒸馏**成一条通用规则：

> 所有 ffmpeg 操作前，先用 ffprobe 验证输入格式兼容性。

从"具体案例"到"通用方法"——这就是 ePro 让 AI 越来越能干的核心机制。

### 六类记忆

ePro 把记忆分成 6 个类别，就像一份人事档案有不同的栏目：

**关于你的信息（AI 用来了解你）：**

| 类别 | 档案类比 | 举例 |
|------|---------|------|
| **个人信息** (profile) | 身份证页 | "用户是前端工程师，在深圳工作" |
| **偏好习惯** (preferences) | 性格备注 | "喜欢 TypeScript，不喜欢写注释" |
| **相关事物** (entities) | 项目经历 | "在做的项目叫 Aurora，用 pnpm" |
| **发生过的事** (events) | 大事记 | "2月15日把数据库从 SQLite 换成 LanceDB" |

**AI 自己积累的经验：**

| 类别 | 档案类比 | 举例 |
|------|---------|------|
| **问题与解法** (cases) | 案例库 | "ffmpeg 编码不统一导致输出损坏 → 先统一再合并" |
| **通用方法** (patterns) | 操作手册 | "外部工具调用前先验证输入格式" |

### 记忆的三层结构

每条记忆不是一坨文字，而是像书一样有不同的"读法"：

| 层级 | 类比 | 用途 |
|------|------|------|
| **L0**（一句话摘要） | 书名 | AI 快速浏览时看这个，判断相不相关 |
| **L1**（结构化概要） | 目录 | 需要更多细节时看这个 |
| **L2**（完整记录） | 全文 | 需要深入了解时才翻开 |

为什么要分层？因为 AI 的注意力也是有限的。如果每次都把所有记忆的全文塞给它，反而会"信息过载"。分层让它**先看书名，觉得相关了再翻目录，必要时才读全文**。

### 全自动运行

整个过程不需要你做任何操作：

1. **对话结束后**（自动记笔记）：ePro 自动分析这次对话，提取值得记住的信息
2. **下次对话开始前**（自动翻笔记）：ePro 搜索相关记忆，悄悄递给 AI
3. **遇到重复信息时**（自动去重）：不会存多份重复笔记，而是合并或跳过

### 技术选择

| 方面 | ePro 的选择 | 为什么 |
|------|------------|--------|
| 运行在哪 | 直接嵌入 OpenClaw | 工作经验不像个人隐私那么敏感，优先追求轻量集成 |
| AI 推理 | OpenAI 兼容 API | 灵活——可以接 OpenAI、也可以接其他兼容的服务 |
| 存储 | LanceDB | 嵌入式数据库，零配置，不需要运行额外软件 |
| 搜索 | 纯向量搜索 | 工作经验主要靠语义匹配，不需要像 memX 那样复杂的多通道搜索 |

## 横向对比：memX vs ePro

| 维度 | memX（用户记忆） | ePro（智能体记忆） |
|------|-----------------|-------------------|
| **一句话定位** | 让 AI 记住你是谁 | 让 AI 记住它做过什么 |
| **类比** | 你的私人日记本 | 员工的工作笔记 |
| **接入方式** | MCP Server（独立服务） | Plugin（内嵌模块） |
| **谁能用** | OpenClaw + Claude Desktop + 任何 MCP 客户端 | 仅限 OpenClaw |
| **运行在哪** | Mac Studio（主节点） | Mac Mini（每个 bot 各一份） |
| **AI 推理** | 全本地 Ollama（零费用） | API 调用（按量计费） |
| **存储** | SQLite + sqlite-vec | LanceDB |
| **搜索方式** | 三通道：向量 + 关键词 + 知识图谱 | 纯向量搜索 |
| **去重策略** | AUDN 四分类：新增 / 更新 / 删除 / 忽略 | 三分类：新建 / 合并 / 跳过 |
| **特色能力** | 记忆衰减、三层晋升、知识图谱、时间线查询 | 六类分类、L0/L1/L2 三层结构、分类感知合并 |

### 为什么技术选择不同？

不是随意选的，每个差异背后都有理由：

**为什么 memX 全本地，ePro 用 API？**
memX 处理的是你的个人隐私——偏好、人际关系、生活事件。这些数据不该离开你的电脑。ePro 处理的是工作经验——"ffmpeg 合并文件前要先检查编码"——不涉及个人隐私，用 API 更灵活。

**为什么 memX 用 SQLite，ePro 用 LanceDB？**
memX 有知识图谱，需要复杂的关联查询（"找出和项目 A 相关的所有人和决策"），SQLite 擅长这个。ePro 主要做向量搜索（"找出和当前任务最相似的历史经验"），LanceDB 更轻量。

**为什么 memX 是 MCP Server，ePro 是 Plugin？**
memX 作为独立服务，可以被多个客户端共享——你在 Claude Desktop 聊天时积累的记忆，在 OpenClaw bot 里也能用。ePro 紧贴 OpenClaw 运行，是专为 OpenClaw bot 设计的。

## 向量搜索：一个类比

memX 和 ePro 都用到了"向量搜索"（Vector Search）。这个词听起来吓人，但原理很直观：

**普通搜索**是按关键词找——你搜"苹果"，只能找到包含"苹果"两个字的内容。

**向量搜索**是按意思找——你搜"水果"，它也能找到关于"苹果""香蕉""橘子"的内容，因为它理解这些词在意思上是接近的。

类比：一个聪明的图书馆管理员。你说"我想看关于做菜的书"，他不会只去找书名带"做菜"的，还会把"食谱""烹饪""厨艺"相关的书也帮你翻出来。

这就是为什么即使你换了说法，记忆系统也能找到之前存过的相关信息。

## 一个完整的例子

假设你第一次告诉 AI：

> "我喜欢用 Tailwind CSS，不喜欢写内联样式。"

**幕后发生的事：**

1. 对话结束后，ePro 自动识别出这是一条「偏好习惯」
2. 创建一条记忆：
   - L0（书名）：用户偏好 Tailwind CSS，不喜欢内联样式
   - L1（目录）：CSS 偏好 — 使用 Tailwind 工具类，避免 inline style
   - L2（全文）：完整的上下文细节
3. 同时，memX 也可能提取到这条偏好，存入用户记忆

**两周后，你开始一个新对话：**

> "帮我写一个登录页面的样式。"

**幕后发生的事：**

1. ePro 在记忆中搜索，找到 CSS 偏好记忆，悄悄递给 AI
2. memX 也提供了你的相关上下文（你是前端工程师，在做项目 X…）

**结果：** AI 直接用 Tailwind CSS 写样式，不问你"要用什么 CSS 方案"，也不会写出你讨厌的内联样式。

## 数据存在哪？

所有数据都在**你自己的设备上**：

| 项目 | 默认路径 | 说明 |
|------|---------|------|
| memX | `~/.memx/memx.db` | SQLite 数据库文件 |
| ePro | `~/.clawdbot/memory/epro-lancedb` | LanceDB 数据目录 |

- 不上传云端
- 不发送给第三方
- 你的数据只属于你

## 常见问题

**Q：我需要手动告诉 AI "记住这个"吗？**
不需要。两个系统都是全自动运行的——对话结束自动提取，下次对话自动注入。

**Q：memX 和 ePro 我需要分别配置吗？**
它们是独立的项目。memX 作为 MCP Server 需要单独安装和配置；ePro 作为 OpenClaw Plugin 跟随 OpenClaw 一起运行。

**Q：只装一个行不行？**
完全可以。它们互不依赖。只装 memX，AI 会记住你的偏好但不会积累工作经验；只装 ePro，AI 会积累经验但不记得你的个人信息。两个都装效果最好。

**Q：它会把所有聊天内容都存下来吗？**
不会。它只提取有价值的信息，而不是逐字存储。就像你听完一场会议，只记重点，不会逐字记录。

**Q：它会让 AI 变慢吗？**
几乎感觉不到。记笔记在对话结束后进行，翻笔记在对话开始前完成，都不影响实时交流。

**Q：如果它记错了怎么办？**
memX 提供了 13 个管理工具（存储、召回、维护、反馈等），可以查看和管理记忆。ePro 的管理工具在后续版本中会加入。
